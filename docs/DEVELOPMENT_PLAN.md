# Elvin: паралельна розробка без ризику для виробництва

## Пріоритети
P0: аналіз креслень реальних шаф, правила, питання лише про невідоме, збереження результатів, перевірка технологом.
P1: окремий 3D-візуалізатор і генератор BAZIS. Не блокують P0.

## Єдиний контракт замовлення (версія 0.1, проєкт)
```json
{
  "schemaVersion": "0.1",
  "orderName": null,
  "sourceImages": [],
  "dimensionsMm": {"width": null, "height": null, "depth": null},
  "materials": [],
  "construction": {},
  "sections": [],
  "facades": [],
  "parts": [],
  "decisions": [],
  "openQuestions": [],
  "warnings": [],
  "review": {"status": "draft", "approvedBy": null}
}
```
Усі критичні значення мають мати provenance: drawing | approved_rule | technologist. null = невідомо, а не 0. Назва замовлення тільки дослівно з креслення чи підтвердження.

## Незалежні етапи
1. ImageAnalysis: фото -> факти та джерела, без припущень.
2. RuleResolver: факти + версія активних правил -> визначені конструктивні рішення.
3. ClarificationPlanner: лише невідомі критичні рішення; дедуплікація за стабільним ID; відповіді записуються в decisions.
4. OrderReview: картка для технолога, явне підтвердження; жоден автоматичний реліз у виробництво.
5. PartsEngine (окремо): затверджена конструкція -> список деталей, координати, кромки.
6. Viewer3D (окремо): лише читає parts; для чернетки допускає позначену попередню геометрію.
7. BazisExporter (окремо): лише затверджені parts та перевірені API; не генерує виробничий файл за неповними даними.

## Гілки і перевірки
- main: стабільний сайт, не змінювати автоматично.
- elvin-3d-test-v2: наявна тестова гілка; майбутні зміни краще розділити на elvin-analysis-* та elvin-geometry-*.
- Кожен PR: що змінилося, приклад до/після, тестові сценарії, статус деплою, відомі обмеження.
- Перевірки P0: не повторювати підтверджені питання; не губити відповіді; не домислювати розміри; показувати частковий аналіз; не називати його затвердженим.
- Перевірки P1: однаковий список деталей для 3D і BAZIS; відсутність невідомих API; без productionReady до технологічної перевірки.

## Обмеження автоматизації
Планувальник може запускати періодичні задачі, але не гарантує безперервного агента чи автоматичного тестування Netlify. Вважати виконаним лише те, що підтверджено GitHub commit, тестом і, за потреби, перевіреним деплоєм.
